## Overall verdict: NOT READY (three blockers, all cheap to fix)

## Must-fix before deploy
1. OpsStack: `BankAcctIfscIN` regex contains `:`, not allowed in CloudWatch Logs custom identifiers; remove it (e.g. `IFSC[ ]*[A-Z]{4}0[A-Z0-9]{6}`) and add a test that every regex uses only the allowed character set.
2. Deploy order deadlock: api `/health` needs the bootstrapped DB, but bootstrap can only run after the compute stack succeeds. Deploy api at desiredCount 0 (or DB-free health check) and scale up after the bootstrap task.
3. KMS key policy deny of non-ViaService Decrypt will probably block RDS/Valkey service access (ViaService applies only to FAS). Add an AWS-service exemption (`aws:PrincipalIsAWSService=false` in the deny) or prove it with a small throwaway probe before the full deploy.
4. Runbook: drop `--require-approval never` (user approves the deploy); do not use `--force` on destroy without being asked.

## Warnings (one line each)
- Nag suppressions: wrong "regenerated every deploy" reason, stale IAM4/monitoring IAM5, stack-wide IAM5 hides future wildcards.
- Plain HTTP on the internal ALB carries bearer tokens and masked text.
- Endpoint SG also admits the whole VPC CIDR on 443.
- RDS postgres log group `/aws/rds/instance/.../postgresql` survives destroy and has no data protection.
- Budget script not idempotent (create twice or delete missing exits non-zero).
- Aadhaar 12-digit rule masks AWS account ids; `\b` support in CWL regex not confirmed by docs.
- sqs_worker has no visibility heartbeat; combined worker RPM can exceed Nova's 10 RPM.
- data-room (2.2 MB) is baked into api/act images that do not need it.
- CDK asset images stay in the bootstrap ECR repo (about 0.05 to 0.15 USD/month).
